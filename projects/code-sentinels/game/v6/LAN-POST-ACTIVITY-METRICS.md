# Optional diagnostics after activity timing

`lan-soak.mjs` reads `game.session.metrics` once from each already running private native observer after the activity loop has finished, or after an existing failure/stop has ended that loop. It writes `post-activity-metrics-blue.json`, `post-activity-metrics-red.json` and a separate combined `post-activity-metrics.json` before closing native sessions. It does not request `viewport.frame` or issue metrics requests inside the valid activity/FPS/tick window. The pre-existing sample list, conservative activity counter, thresholds and pass/fail conditions are unchanged.

These values are bounded native timing rings from the last active session, not a complete trace of every prior epoch or an extra performance sample. The read can help distinguish `prepareUploads`, rendering/readback and simulation costs, but cannot retrospectively assign every earlier FPS dip to a cause. RPC timeouts and storage errors remain optional diagnostic errors; they never replace an existing failure or make a failed test pass. Collection is one-shot, including when a later replay assertion fails after a successful activity interval.
